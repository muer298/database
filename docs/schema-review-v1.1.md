# A 分支数据库设计审查记录（v1.1）

审查对象：`a/schema-v1.1`（提交 `7073eff`）  
审查结论：有条件通过；以下问题修正并通过 MySQL 8.4 空库验收后，作为第二周开发基线合并到 `main`。

## 接受的 A 成员变更

- 接受 `movies.release_date NOT NULL`，使 `(title, release_date)` 唯一约束对全部电影记录生效。
- 接受 8 张表的关系模式、完整性约束、索引方案以及 v1.1 查询脚本。
- 接受扩充后的用户、电影、影厅、座位、场次、订单与电影票测试数据。

## 联合审查时完成的修正

1. 为每个场次对应影厅的全部启用座位初始化占用记录，测试数据由 18 条补齐为 100 条。
2. 为已退款订单保留 `REFUNDED` 历史票，同时确保当前座位恢复为 `AVAILABLE` 且不再关联订单。
3. 将已结束场次的历史票改为 `USED`。
4. 售票数和票房统计统一统计 `VALID`、`USED`，排除 `REFUNDED`。
5. 将按片名查询影片的单值子查询改为 `IN`，避免同名不同上映日期影片导致多行错误。
6. 明确固定主键测试数据只用于独立空测试库，不宣称可安全混入任意现有业务库。
7. 纠正规范化分析：可空的 `phone`、`email` 不作为候选码；票面排号、列号是出票时快照，不存在 `seat_id` 对快照的恒定函数依赖。
8. 明确 `movies.actors` 目前只是展示文本；出现演员级检索需求时再拆分 `actors`、`movie_actors`。

## 验收结果

- MySQL 8.4：建表、插数和 8 条查询均执行成功。
- 表数量：8。
- 数据量：10 用户、10 电影、10 影厅、100 座位、10 场次、10 订单、100 场次座位、15 电影票。
- 每个场次的占用记录数与对应影厅启用座位数一致。
- 已退款票保留历史，座位状态为 `AVAILABLE`、当前订单为空。
- 已结束场次不存在非 `USED` 电影票。
- Maven：`mvn clean test` 通过。

后续字段、状态或约束如需变化，A 与 B 必须同时更新 `schema-contract.md`、SQL、README 和 Java 映射。
